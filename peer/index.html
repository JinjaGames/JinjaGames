      How it works

      1. One side creates an invite code, the other pastes it and creates a reply code.
      2. The reply code goes back and the two devices connect directly.
      3. Compare the verification code on both screens, then send. Either side can send and receive.

      Works with the JinjaPeer apps

      This is the same protocol (v1) as the JinjaPeer Windows and Android apps. You can send between web and app, web and web, in both directions, as the one who invites or the one who joins.

      What your browser supports

        Security in plain words

        Signed codesEvery code is signed (Ed25519). If a single character is altered it is rejected.
        Fresh keys every timeEach connection uses new one time keys (X25519), so old recordings cannot be opened later.
        Encrypted twiceEvery frame is encrypted and authenticated (ChaCha20 Poly1305) on top of WebRTC's own DTLS. A replayed, reordered or changed frame cuts the connection.
        Verification codeA 60 bit code derived from both codes. A man in the middle cannot make both screens show the same one.
        Every file is checkedSHA 256 is verified on arrival. A file that does not match is not saved.
        You decideNothing is written before you accept. File names are cleaned, nothing overwrites an existing file, nothing is opened automatically.

        Network note

        File data never touches a server. To find a route between two networks the browser asks public STUN servers (Google and Cloudflare) which address it appears as; this reveals your public IP address to them, like any video call does. Very strict networks may need your own TURN relay (Settings); data stays end to end encrypted even then.

        Honest limits

        • If you do not compare the verification code and the channel you used to exchange codes is hijacked, someone in the middle is possible. Compare it.
        • The identity key of this browser is stored in this browser (like the app stores it on the device). Clearing site data creates a new identity.
        • Both pages must stay open during a transfer. Reconnecting needs new codes.
